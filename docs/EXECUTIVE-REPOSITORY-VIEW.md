# Executive Repository View

## Purpose

This document explains how the repository connects strategy, capability,
applications, technology, governance evidence and target-state delivery.

## End-to-end two-dimensional line

```text
STRATEGY DIMENSION
Strategic objective
        |
        v
BUSINESS DIMENSION
Business capability -> business owner -> maturity -> criticality
        |
        v
APPLICATION DIMENSION
Application -> lifecycle -> hosting -> information classification
        |
        v
TECHNOLOGY DIMENSION
Asset -> vendor -> version -> support horizon -> architecture layer
        |
        v
GOVERNANCE DIMENSION
Standard -> compliance -> waiver -> risk -> decision
        |
        v
PLANNING DIMENSION
Roadmap -> lifecycle forecast -> investment action -> target state
        |
        v
REUSE DIMENSION
Reference architecture -> pattern -> building block -> control evidence
        |
        v
ASSURANCE DIMENSION
Traceability score -> alignment score -> review -> audit evidence
```

## Executive questions answered

| Executive question | Repository evidence |
|---|---|
| What capability depends on the solution? | Capability and application links |
| Who owns the business and technology outcomes? | Business, technology, risk and roadmap owners |
| Is the technology supported and strategic? | Lifecycle, support date and standards status |
| Is an exception being used? | Waiver status, expiry, controls and remediation |
| What risk remains after controls? | Inherent and residual risk assessment |
| What is the transition plan? | Roadmap, milestones and target date |
| What should receive investment? | Investment action and priority |
| Is there an approved reusable design? | Reference architecture and pattern alignment |
| Can the decision be audited? | Decision and evidence references |
